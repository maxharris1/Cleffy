## What changed

### 1. A gesture that starts mid-settle (`src/features/viewer/PdfViewport.tsx`)

- **The bug:** the settle glide checked for a pointer only when it started. Ink never replaces the store's view, so the glide kept running under a stroke, and a pan's first clamped move snapped the rest of the way.
- **Pointerdown stops the glide.** A capture-phase `pointerdown` listener on the score runs ahead of the GestureController. It cancels any settle glide where it is. If the view is still above the top bound, it keeps that position as top slack (`slackTopRef ??= scrollY`). Pointers that start on `[data-ui-overlay]` are ignored, as the controller ignores them.
- **Every pointer kind is covered:** ink, pan and multi-pointer.
- **Because the slack is set before the controller's first move,** a pan moves with the finger and never snaps.
- **The rest settles on release.** The existing window `pointerup`/`pointercancel` handler resumes the settle. Since `settleIntoBounds` waits while `gestureRef.pointerActive`, that happens only when the last pointer lifts.
- **Unmount** removes the listener and cancels the glide (shared `cancelSettleGlide`).

### 2. Reanchoring at the bottom bound (`src/features/viewer/geometry.ts`)

- **The bug:** `reanchorView` picked its anchor page with `focusedPageIndex`. That function's bottom-bound override names the last row, which can be far below the centre when zoomed out.
- **The fix:** the nearest-middle search is now a separate private function, `pageAtUncoveredCenter`. `reanchorView` uses it directly, so the anchor is chosen by geometry alone.
- **The pager is unchanged.** `focusedPageIndex` keeps both endpoint overrides (top = page 1, bottom = last row) and falls back to the same search, so fix pass 2's Next/Previous endpoint behaviour holds. The new test also asserts `focusedPageIndex` still returns the last page in the packet's scenario.

### 3. Playback follow vs the dismissal settle (`src/features/playback/PlayheadController.ts`)

- **What happens:** `stepFollowAnimation` now calls `rebaseFollowAnimation` before each write. That clamps the glide's target against the current layout, viewport and strips (`getObscured`, which includes the notice inset). If clamping moves the target, the glide restarts from the live view toward the clamped target.
- **Why it fixes the bug:** a follow write still makes the viewer's settle step aside (it gives way to any other move). But the follow glide now ends inside the new bounds, so the settle's work is done by the handoff.
- **A pending settle also survives an interrupted follow.** If a user gesture stops the follow part way, fix 1's pointerdown turns any view still out of bounds into slack and settles it on release.

## Open questions

1. A pointerdown on the score while the view is out of bounds above the top now always holds that position as slack until release, not only during a settle glide. The only way to get there is a tightened top bound, so it amounts to the same thing. It also covers a follow glide that a gesture stops part way. Say if you'd rather limit it to an active glide.
2. When the bounds move under a follow glide, the glide restarts its full 280 ms from the live view toward the clamped target, instead of finishing the remaining time. That avoids a jump, but a re-aimed glide can run up to 280 ms longer.
3. The browser check used notice cards added to the real notice region, not a real Dismiss click (see Setup). If you want a real Dismiss in the browser too, the cheapest real one locally is the access-changed notice: share a seeded score with the student as editor, then change the role.
