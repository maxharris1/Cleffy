### What changed, briefly

- **D1**: new migration `supabase/migrations/20261020180600_read_only_seats_enforced.sql`.
    - `seat_read_only(uuid)` (service role only) and `caller_seat_read_only()` (the caller's own answer). Both read `resolve_entitlements()`, so a seat goes read-only the moment the clock or a row moves it.
    - Restrictive policies added beside the existing permissive ones: annotations insert and update, annotation_snapshots insert, share_links insert, and broadcast on `doc:%`. They don't recreate any other branch's policy, so #63's realtime takedown changes can't be undone by this one.
    - Triggers: `assignments` (`assign_score` is a definer function), and a score's `title` / `content_rev` changes.
    - The check is on the **caller**, so a roster student's Edit is unchanged.
    - Client: the sync engine holds a change refused for a read-only seat instead of undoing it (reason `seat-read-only`), and the banner has its own copy.
- **D3**: `subscriptions.ended_at` is written by the webhook (`endedAtOf` in `stripeEvents.ts`) through a new defaulted `p_ended_at` on `write_subscription_under_lock`, which keeps the stored value over a null. The derivation reads only that once the status is terminal, and null before.
- **D2**: `district_billing_rederive(studio)` recomputes from scratch. The result is null while the owner has any live Stripe Invoicing Academy subscription, whatever the record or override still names. It is called from subscription writes (which also relink from an ended subscription to a live replacement when no override decides), the override trigger, and the admin's hand-back to Stripe. Admin pins are left alone.
- **D4**: found while writing the proof: the old cross-column check let a **date with no source** through, because `contract_ends_source = 'admin'` is NULL when the source is NULL. It now reads `is not distinct from 'admin'`.

## Open questions

1. **Admin pins on renewal.** Following Codex, an admin-pinned `contract_ends_at` is kept when the district renews on a new subscription. If an admin pinned a past date and then the district renewed without the pin being updated, #64 would still purge. Should a live replacement subscription clear an admin pin that is already in the past?
2. **District moving to card-paid Academy.** "Paying" means a live **Stripe Invoicing** Academy subscription of the owner. A district that ended its contract and moved to ordinary card-paid Academy keeps its contract end (the existing tested behaviour: "the card subscription did not touch the district's contract end"), so #64 would purge its district data. Is that intended, given the owner is still paying?
3. **resend-inbound bypasses the mail budget.** The support-mail forward (`resend-inbound/index.ts:208`) does not go through the shared budget. It is pre-existing and in #64's file set; it should be fixed on one branch (#64 or a follow-up), not both.
4. **Collaborator edits before the sweep.** Read-only enforcement is on the writer. Another, non-read-only collaborator can still edit a read-only teacher's **own** score until `reconcile` archives it: at once on any event, at most an hour on the clock alone. Fine under decision 2, which is about the seat holder.
5. **Owner-only sharing actions.** `set_document_member_role`, which an owner uses to change a collaborator's role, is not blocked for a read-only seat. It isn't an invite, and the score is archived. `redeem_share_link` is allowed too: joining is harmless, because RLS refuses any edits after.
