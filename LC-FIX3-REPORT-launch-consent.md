## Open questions (things I would otherwise have asked another session or Max)

1. **District context in the app:** should the add-student form offer "for district X" to seated teachers, and should a district admin be able to bulk-provision? Either way it would call the existing `districtStudioId`. Should #61's district-seats UI own the RPC that lists a teacher's district studios?
2. **Read-only seats (#61) and provisioning:** `district_provisionable` accepts any current seat. After #61 merges, should a **read-only** seat be refused (using #61's writable-seat helper)? That cannot be done here without a dependency on #61's helper. It is suggested as a one-line follow-up after the #61 → #64 merge.
3. **Legacy district students:** with no positive evidence in the schema, the migration's own backfill run attributes **no** legacy rows. Any students provisioned for a district before this deploys stay unattributed (and never purged) until a district's records are entered with `admin_record_district_evidence` and the backfill is re-run. That is the "when in doubt, don't" outcome. Max should confirm that this is the intended launch posture. In practice district_billing only exists once #61 deploys, so the window is small.
4. **Classes / invite records:** the packet's "created in a district-org class" branch has no data to read, because Cleffy has no classes. If classes are added later, they should carry the district id and feed `district_student_evidence`, or the provisioning trigger.
5. **Seat history before this migration:** seats removed before 20261021120800 left no record (studio_members forgets them), so their tenures start empty. Legacy students of teachers who left before the deploy cannot be attributed automatically even with evidence; an admin correction (`admin_set_student_district`) is the path. Should #61 keep a seat history of its own, so this is covered from the moment #61 deploys?
6. **Edge-function E2E in cloud sessions:** the local edge runtime cannot reach npm through the proxy (an untrusted CA). The session-start or cloud-up hook may need to hand the CA bundle to the edge-runtime container for future function-level tests.
7. **`.env.local` and the syncEngine backoff test:** the test is sensitive to the local stack's `.env.local`. This is pre-existing; worth a ticket so local runs match CI.
8. **#61 trigger coexistence:** #61 adds `studio_members_release_seat` (AFTER DELETE) and a `kept_active` column. #64 adds `studio_members_seat_tenure` (AFTER INSERT OR DELETE). The names differ and they don't conflict, but the combined tree is untested; run `district_student_scope.sql` and #61's seat proofs after the merge.
